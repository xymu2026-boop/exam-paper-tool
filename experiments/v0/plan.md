## 1. V0 实验目标

### V0 只回答一个问题

> **"在真实家庭试卷/练习册照片上，能不能把手写答案、红笔批改、草稿痕迹擦掉，同时不破坏题干、公式、图形和表格？"**

### V0 不回答的问题

| 问题 | 为什么 V0 不回答 |
|------|-----------------|
| 能不能全自动？ | V0 用人工框选，不测试全自动 |
| 能不能批量处理？ | V0 只有 5 张样本 |
| 能不能做错题本？ | 擦除和错题整理是两件事 |
| 能不能做学习闭环？ | 太远了 |
| 能不能做漂亮界面？ | V0 在命令行/脚本层面验证 |
| 哪条技术路线最好？ | V0 同时测试涂白和 inpainting，对比后才有结论 |

### V0 必须得出的结论

1. 哪种擦除方式更适合真实样本（涂白 vs inpainting）
2. 哪类图片能处理，哪类不能
3. 当前方案的能力边界在哪里
4. 是否值得进入 V1

## 2. V0 技术路线

V0 只用三条路线，不引入复杂方案：

### 路线 A：红笔/蓝笔颜色阈值识别（辅助）

**做什么**：自动找出红色和蓝色笔迹区域，生成建议框。

**怎么做**：
1. 将图片从 RGB 转到 HSV 色彩空间
2. 设置红色范围（H ≈ 0-10 或 160-180）和蓝色范围（H ≈ 100-130）
3. 生成二值 mask（红/蓝区域 = 白色，其他 = 黑色）
4. 对 mask 做膨胀，覆盖笔迹边缘
5. 从 mask 提取轮廓矩形，作为"建议擦除区域"

**输出**：一组建议框坐标 `{x, y, w, h}`

**地位**：辅助路线。自动标记出红笔区域，减少人工框选量。如果误标，人工可以删除。

### 路线 B：人工确认区域 + 涂白（主线之一）

**做什么**：人工确定哪里该擦，程序把该区域变成纸张背景色。

**怎么做**：
1. 人工标注待擦除区域的坐标
2. 程序读取该区域的背景色（采样区域边缘像素的众数）
3. 将该区域填充为该背景色

**输出**：涂白版干净图

### 路线 C：人工确认区域 + OpenCV inpainting 修复（主线之二）

**做什么**：人工确定哪里该擦，程序用 inpainting 算法根据周围像素修复背景。

**怎么做**：
1. 人工标注待擦除区域的坐标
2. 将标注区域生成 mask 图像
3. 使用 OpenCV `cv2.inpaint()` (INPAINT_TELEA 算法) 修复

**输出**：修复版干净图

### V0 不做的事

- ❌ 不做 OCR
- ❌ 不做深度学习
- ❌ 不做云端多模态识别
- ❌ 不做自动版面分析
- ❌ 不做全自动区域检测（除了颜色阈值辅助）

## 3. V0 样本选择原则

### 为什么只选 5 张

| 数量 | 问题 |
|------|------|
| 1 张 | 看不出问题，可能刚好样本太简单 |
| 5 张 | 刚好能覆盖几种典型场景，发现共性问题 |
| 10 张 | 对 V0 来说太多，不如 5 张做深做透 |
| 50 张 | V0 不是批量测试阶段 |

### 5 张样本应覆盖的场景

| # | 场景 | 验证什么 |
|---|------|----------|
| 1 | 纯白试卷背景 + 红笔批改 | 颜色分离 + 基础擦除能力 |
| 2 | 练习册横线/格子 + 手写答案 | 背景线条保留 + 手写擦除 |
| 3 | 红笔批改 + 黑笔/铅笔答案混合 | 多层叠加处理能力 |
| 4 | 含公式/几何图形的数学题 | 图形保护能力 |
| 5 | 手写和印刷同色 + 涂改复杂 | 方案能力边界（最难场景） |

### 选择标准

- 已在分类表中标记为"可擦除"
- 适合还原空白题目 = "是"
- 不含疑似隐私信息
- 能够代表真实使用场景

复制后验证：用 `shasum` 确认副本和原图字节一致。

- 需要擦除的区域坐标（人工标注）

打开图片，用坐标标注要擦除的区域。

```json
  "sample_id": "V0-S1",
  "regions": [

    {"id": 2, "x": 300, "y": 400, "w": 120, "h": 45, "reason": "红笔订正文字", "method": "whiteout"}
  ]
}
```

### 第 4 步：同一张图分别生成涂白版和 inpainting 版

对每张样本的每个擦除区域，执行两条路线：

| 版本 | 方法 | 输出文件名 |
|------|------|----------|
| 涂白版 | 采样背景色 → 填充 | `V0-S1_涂白版.jpg` |
| 修复版 | OpenCV inpaint | `V0-S1_修复版.jpg` |

### 第 5 步：生成三连对比图

将原图、涂白版、修复版并排拼接成一张对比图，方便青山一眼看出差异。

输出到：`02_V0擦除实验/对比图/V0-S1_三连对比.jpg`

## 7. 评分标准

### 10 分制评分

| 维度 | 分数 | 评判方法 |
|------|------|----------|
| **手写/批改是否擦干净** | 0-2 分 | 2分=完全消失；1分=微量残留；0分=大量残留 |
| **题干是否完整无误伤** | 0-2 分 | 2分=完全保留；1分=轻微痕迹但可读；0分=文字被破坏 |
| **公式/图形/表格是否完整** | 0-2 分 | 2分=无任何损伤；1分=轻微变形但不影响理解；0分=破坏性损伤 |
| **背景是否自然** | 0-2 分 | 2分=和周围一致；1分=轻微色差/模糊；0分=明显补丁感 |
| **是否可打印重练** | 0-2 分 | 2分=打印出来像空白卷；1分=打印后有小瑕疵但不影响使用；0分=不能打印 |

### 总分解释

| 分数 | 档次 | 含义 |
|------|------|------|
| 9-10 分 | ⭐⭐⭐ 优秀 | 可直接打印，不需要任何修改 |
| 7-8 分 | ⭐⭐ 可用 | 可打印使用，可能有轻微瑕疵 |
| 5-6 分 | ⭐ 勉强 | 只能用于参考，不建议直接打印 |
| 0-4 分 | ❌ 失败 | 不能使用 |

### 硬性失败规则

**只要出现以下任何一种情况，该样本直接判为失败，不计算总分：**

1. 题干文字被误删，导致题目内容不完整
2. 数学公式符号丢失（分数线、根号、求和符号等）
3. 几何图形线条断裂（三角形缺边、圆形缺弧、辅助线消失）
4. 表格关键线条被破坏
5. 修复算法生成了影响理解的伪影（凭空出现的纹理、色块）
6. 擦除后题干文字变得模糊不可读

**这些是不可接受的底线**，一旦触发，说明当前方案对该类样本不适用。

## 8. V0 成功/失败判断

### 实验成功条件（可以进入 V1）

- ✅ 5 张样本中 ≥3 张达到 **7 分以上**
- ✅ **0 张**出现硬性失败（题干/公式/图形被破坏）
- ✅ 能明确总结出"哪类图片适合涂白，哪类适合 inpainting"
- ✅ 能列出当前方案**能处理**和**不能处理**的图片类型清单

### 实验"失败"的三种可能

失败不意味着项目失败，而是说明当前方案需要调整。可能的失败原因和应对：

| 失败原因 | 应对 |
|----------|------|
| 涂白和 inpainting 效果都不好（尤其是 inpainting 模糊） | 调整 inpainting 参数（半径、算法）；或考虑对特定图片只做涂白 |
| 样本 5（同色手写）效果极差 | 承认纯半自动方案在同色手写场景有先天局限；V1 需引入字体/笔画特征分析 |
| 几何图形样本（样本 4）出现问题 | V1 必须引入"图形保护区域"概念，在擦除时排除图形边界 |

### 无论成功还是失败都必须产出

- 5 张样本的完整评分记录
- 能处理/不能处理的图片类型清单
- V1 优先解决什么问题
- 当前方案的能力边界声明
