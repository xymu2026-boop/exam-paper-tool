# 试卷宝技术路线对比报告

> 生成时间：2026-05-25
> 目的：站在"家庭试卷擦除"这个具体场景下，对比每条技术路线的适用性
> 不是泛泛的技术介绍，而是有明确推荐结论的决策参考

---

## 路线 1：Pillow 颜色阈值

### 能解决什么
- 红色笔迹（红勾、红叉、红圈、红字订正）的自动检测和擦除
- 蓝色笔迹的自动检测和擦除（如果蓝笔颜色和印刷黑有明显差异）
- 非常简单快速，规则透明可解释

### 不能解决什么
- 黑笔、铅笔答案（颜色和印刷字几乎一样，阈值无法区分）
- 彩色题目/彩色图形/红色下划线的误伤问题（会把这些当红笔擦了）
- 拍照偏色导致阈值不稳定（同一支红笔在不同光线下 RGB 值差异很大）
- 无法判断"这个红像素是批改还是题目自带红色标记"

### 对试卷宝的价值
- **辅助价值**：自动标记明显红笔区域，减少人工框选量
- **不能作为主力**：因为有误伤风险和覆盖不全

### 主要风险
- 误伤彩色题目、红色重点标记、几何图的彩色辅助线
- 拍照色偏导致漏检或过度检测
- 对铅笔/黑笔/圆珠笔完全无效（恰恰是最常见的手写工具）

### 是否适合 V0
✅ 适合作为**辅助路线**——自动标记红笔建议区，人工复核后再擦除

### 是否适合 V1
✅ 适合作为预处理步骤——自动标记 + 人工确认，节省框选时间

### 是否适合未来
✅ 一直可以作为辅助工具保留，但不指望它单独解决所有问题

### 对 Mac mini 是否友好
✅ 非常友好。Pillow 只有 10MB，纯 Python，无编译依赖

### 是否涉及隐私风险
❌ 不涉及。完全本地处理

### 结论
**做辅助不做主力。** 先用它自动标红笔，省掉一些人工框选的功夫。但不能指望它单独完成任务。

## 路线 2：人工框选 + 涂白

### 能解决什么
- 任何位置的任何手写痕迹（因为是人判断的，不依赖颜色、字体、版式）
- 简单可靠，不会引入"修复算法的意外效果"
- 适合纯白背景的试卷

### 不能解决什么
- 涂白会破坏背景横线和格子（练习册的线条被同时涂掉）
- 涂白区域可能和周围背景有色差（白得不自然）
- 大面积涂白会让纸张看起来像打了补丁
- 需要人参与，不能全自动

### 对试卷宝的价值
- **V0 主力方案之一**：最简单、最可靠、最不容易出错
- 适合纯白背景的试卷（约 30-40% 的真实样本）

### 主要风险
- 横线/格子练习册涂白后看起来不自然
- 如果框选稍微不准，会留下笔迹或擦掉题干

### 是否适合 V0
✅ **主力方案**

### 是否适合 V1
✅ 保留作为选项——当 inpainting 效果不佳时，涂白是可靠的后备

### 是否适合未来
✅ 始终保留，但逐渐让 inpainting 承担更多场景

### 对 Mac mini 是否友好
✅ 非常友好。只需要 Pillow 读写图片和填充颜色

### 是否涉及隐私风险
❌ 不涉及

### 结论
**V0 的底线方案。** 如果 inpainting 搞砸了，至少有涂白兜底。对纯白试卷效果最好。

## 路线 3：OpenCV inpainting 修复

### 能解决什么
- 擦除手写后，用周围像素推断补回背景（比涂白更自然）
- 能补回横线、格子、纸张纹理
- 对大面积和小面积擦除都适用

### 不能解决什么
- 大面积修复可能产生模糊或伪影
- 如果手写覆盖了印刷题干，inpainting 无法恢复被覆盖的印刷内容
- 参数需要根据图片质量调整（修复半径、算法选择）
- 不能自动判断哪里需要擦（仍然需要人工框选或颜色阈值配合）

### 对试卷宝的价值
- **V0 主力方案之二**：和涂白做对比，看哪个更好
- 对练习册（有横线/格子）效果显著优于涂白

### 主要风险
- 大面积修复模糊（修复半径不够大时，修复区域的纹理可能不自然）
- 在图形边缘附近修复可能产生"涂抹效果"
- 需要 OpenCV 库（80MB，但安装简单）

### 是否适合 V0
✅ **主力方案**（和涂白对比）

### 是否适合 V1
✅ 保留为主力修复算法

### 是否适合未来
✅ 可以一直使用。后续可尝试不同 inpainting 算法（Navier-Stokes vs Fast Marching）

### 对 Mac mini 是否友好
✅ 友好。`pip install opencv-python`，Apple Silicon 有预编译包

### 是否涉及隐私风险
❌ 不涉及

### 结论
**V0 重点测试的方案。** 预期比涂白效果好，但需要实测验证。是进入 V1 的默认修复算法。

## 路线 4：OCR + 重排

### 能解决什么
- 识别印刷题目的文字内容
- 重新排版生成干净的空白题目（文字清晰，版式统一）
- 适合纯文字题（如语文阅读理解、英语填空）

### 不能解决什么
- **数学公式**：分数线、根号、积分符号 OCR 极易出错
- **几何图形**：无法通过文字描述重排，必须保留原图
- **表格题**：版式重建复杂，容易错位
- **混合排版**：中文、英文、符号、公式混排，OCR 错误率很高
- **OCR 错误导致题目内容出错**：这是最严重的后果——学生做的题目可能已经被改写了

### 对试卷宝的价值
- **远期价值**：等擦除流程稳定后，OCR 可以辅助做错题卡（识别题号、题目文字）
- **当前价值低**：V0/V1 阶段用不上

### 主要风险
- 数学公式 OCR 是业界公认难点，不是装个库就能解决的
- 需要额外安装 OCR 引擎（PaddleOCR ~500MB，Tesseract 需要训练中文数据）
- OCR 错误会悄悄改变题目内容（最危险的风险类型）

### 是否适合 V0
❌ 不适合。V0 不涉及任何 OCR

### 是否适合 V1
🚧 可能作为辅助——只识别题号（帮助分割题目区域），不识别完整题目内容

### 是否适合未来
✅ V2 阶段可引入，用于：
- 辅助识别题号
- 辅助判断题目区域边界
- 生成错题卡时提供题干文字摘要

### 对 Mac mini 是否友好
⚠️ PaddleOCR 可以本地运行（~500MB），Tesseract 需要 `brew install tesseract`

### 是否涉及隐私风险
❌ 本地运行不涉及，但如果用百度 OCR API 则涉及

### 结论
**当前不做。V2 再考虑。** 即使 V2 引入，也只用于辅助题号识别，不做完整题目 OCR 重排。

## 路线 5：本地视觉模型/深度学习分割

### 能解决什么
- 自动区分手写区域和印刷区域（不依赖颜色，基于笔画特征）
- 如果训练好，是全自动方案中效果最好的
- 可以学会忽略横线、格子、表格等背景元素

### 不能解决什么
- 需要标注数据（几百到几千张，每张标注手写区域的 mask）
- 训练和推理需要一定算力
- 可能把特殊字体或手写风格的印刷字误判为手写
- 模型可能产生"幻觉"，在某些样本上完全崩溃

### 对试卷宝的价值
- **远期价值极高**：如果跑通，可以大幅减少人工框选
- **当前价值低**：没有标注数据、没有训练流程、没有评估基准

### 主要风险
- 标注成本高（至少需要几百张标注过的样本）
- 需要模型训练经验（选模型、调参数、防过拟合）
- 模型部署到 Mac mini 上推理速度可能不够快
- 对"没见过的新题型"泛化能力不确定

### 是否适合 V0
❌ 不适合

### 是否适合 V1
❌ 不适合

### 是否适合未来
✅ V3 阶段探索方向。条件：
- V0-V2 积累了足够的标注数据（每次人工框选就是一次标注）
- 有 200+ 张带标注的样本
- 青山愿意投入时间验证模型效果

### 对 Mac mini 是否友好
⚠️ 推理可以（M 芯片有 Neural Engine），但这些模型的推理速度可能较慢
训练建议用云端 GPU

### 是否涉及隐私风险
⚠️ 如果模型在本地训练和推理，不涉及隐私。但如果用云端 GPU 训练，需要注意训练数据是否脱敏

### 结论
**V3 的探索方向。** 现在不需要考虑。但 V0-V2 的人工框选数据可以存下来，为未来训练打下基础。

## 路线 6：云端多模态模型

### 能解决什么
- 用 GPT-4V / Claude Vision 看图片，直接判断"手写区域在哪里"
- 可以处理规则和传统算法搞不定的复杂情况

### 不能解决什么
- 不能保证每次判断一致（同一个图两次调用可能结果不同）
- 不能保证不误判（模型也可能看错）
- 不能调试（不知道为什么判断错了，只能换 prompt 重试）

### 对试卷宝的价值
- **价值有限且风险高**：隐私风险 > 技术收益
- 可能用于：遇到特别难的样本，人工判断也不确定时，用云端模型给第二个意见

### 主要风险
- **隐私**：试卷图片含孩子笔迹、可能含姓名学校，上传到 OpenAI/Anthropic 的服务器
- **成本**：按 token 计费，虽然不贵但不适合批量
- **不可控**：模型可能产生幻觉
- **违反家庭学习隐私原则**

### 是否适合 V0
❌ 不适合

### 是否适合 V1
❌ 不适合

### 是否适合未来
⚠️ 谨慎使用。如果要测试，必须满足三个条件：
1. 青山明确授权
2. 只用于不含隐私信息的样本
3. 不作为默认流程，仅作为疑难样本的人工辅助参考

### 对 Mac mini 是否友好
❌ 必须联网。可以调用 API，但延迟取决于网络

### 是否涉及隐私风险
🔴 **涉及**。图片上传到第三方服务器

### 结论
**暂不进入默认流程。** 除非遇到传统方法完全无法处理的场景，且青山明确授权使用云端模型。

## 综合推荐结论

### V0 推荐

```
人工框选 + 涂白/inpainting 对比（主线）
颜色阈值识别红笔（辅助）
```

理由：
- V0 的核心问题是"能不能擦"，不是"能不能自动擦"
- 人工框选保证了不误删题干这个硬底线
- 涂白和 inpainting 对比，找到各自适合的场景

### V1 推荐

```
本地网页标注界面 + OpenCV 预处理 + 半自动擦除
颜色阈值 + 人工框选 + inpainting（默认）/ 涂白（后备）
```

理由：
- 需要让青山能用起来，所以加简单界面
- 预处理做裁切、旋转，减少人工操作
- inpainting 作为默认修复方式，涂白作为后备

### V2 推荐

```
引入 OCR（仅用于题号/题目区域识别，不做完整重排）
错题收集 + 错题重练卷生成
```

理由：
- OCR 不用于重排题目（数学公式/图形保护）
- 只用于辅助识别题目边界和题号
- 让错题整理变成可能

### V3 推荐

```
在积累足够标注数据后，训练本地小模型识别手写区域
目标是"大部分自动 + 少数人工确认"
```

条件：V0-V2 积累了足够的标注数据（≥200 张）
不要急于启动

### 云端多模态

```
不进入默认流程
除非青山明确授权且样本不含隐私
仅作为"疑难样本人工第二意见"的参考
```
